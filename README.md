# CQA — оценка качества диалогов поддержки

**Команда / Team: Vamp Vibe Coders**

Приложение проверяет, как оператор поддержки провёл диалог, по настраиваемому чек-листу: приветствие, идентификация
клиента, качество консультации, вежливость, грубые ошибки и т. д. Оценку делает **собственная модель `cqa-local-v1`**,
обученная с нуля. Она работает на обычном процессоре без интернета и бесплатно, никакие внешние ИИ-сервисы не нужны.

Что умеет:
- **Оценка:** по каждому критерию даёт ответ, вероятность, объяснение и ссылку на реплику-доказательство. Считает итоговый
  балл, итоги по секциям и отдельный флаг грубой ошибки. Понимает чаты и звонки на русском, казахском и английском.
- **Чек-лист:** в редакторе можно добавить, изменить или удалить критерий, без правки кода. Каждое сохранение создаёт
  новую версию.
- **Апелляции:** оператор оспаривает оценку, проверяющий подтверждает или меняет её, итог пересчитывается.
- **Дообучение:** по решениям проверяющих модель можно дообучить одной кнопкой.
- **Аналитика:** сводка для руководителя, профили операторов, лента тревог о грубых ошибках.

## 1. Что нужно установить (один раз)

| Программа | Версия | Где взять |
|---|---|---|
| Node.js | 20 или новее | https://nodejs.org (кнопка LTS) |
| Python | 3.10 или новее | https://www.python.org/downloads/ — при установке отметить **«Add python.exe to PATH»** |

Интернет нужен только для установки: около 300 МБ пакетов, в основном PyTorch.

## 2. Установка проекта (один раз)

Распакуйте папку проекта и дважды щёлкните **`setup.cmd`**. Скрипт:
1. ставит пакеты приложения (`npm install`);
2. создаёт Python-окружение `local-model\.venv`;
3. ставит туда PyTorch для процессора и остальные пакеты модели;
4. создаёт файл настроек `.env` из `.env.example`.

Это занимает 2–5 минут. В конце появится «Done. To start the app run start.cmd». Сообщения скриптов на английском: русские буквы в `.cmd`-файлах ломают командную строку Windows.

<details><summary>То же самое вручную, командами (PowerShell или cmd из папки проекта)</summary>

```
npm install
py -3 -m venv local-model\.venv
local-model\.venv\Scripts\python.exe -m pip install --upgrade pip
local-model\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu --extra-index-url https://pypi.org/simple
local-model\.venv\Scripts\python.exe -m pip install -r local-model\requirements.txt
copy .env.example .env
```
</details>

## 3. Запуск

Дважды щёлкните **`start.cmd`**. Откроются два окна и браузер:
- **«CQA model»** — сервис модели на http://127.0.0.1:8000. Он загружается 5–10 секунд.
- **«CQA app»** — само приложение на **http://localhost:3000**.

Чтобы остановить, закройте оба окна.

<details><summary>Запуск вручную, в двух окнах терминала</summary>

```
local-model\.venv\Scripts\python.exe local-model\serve.py
```
```
npm start
```
Затем откройте http://localhost:3000. Проверить, что модель жива: http://127.0.0.1:8000/health.
</details>

## 4. Как пользоваться

В архиве уже есть оценки всех 65 диалогов учебного набора DEV, поэтому экраны не пустые. Роль переключается справа
вверху: **Оператор** или **Проверяющий**. Это демонстрационный переключатель, паролей нет.

| Экран | Что там делать |
|---|---|
| **Сводка** | Средний балл, грубые ошибки, апелляции, проблемные критерии, разрезы по языкам, каналам и операторам, блок «Экономия» |
| **Диалоги** | Список диалогов. Отметьте нужные и нажмите **«Оценить выбранные»** или **«Оценить все»**: 65 диалогов оцениваются за 5–15 секунд |
| **Карточка диалога** (клик по диалогу) | Слева транскрипт, справа оценка по критериям (подробнее ниже) |
| **Операторы** | Профиль оператора: средний балл против команды, динамика, слабые критерии, план коучинга |
| **Тревоги** | Грубые ошибки со ссылкой на реплику; можно отметить просмотренной с заметкой |
| **Апелляции** | Очередь апелляций и решения по ним, а также блок «Дообучение модели» |
| **Чек-листы** | Редактор критериев: формулировка, вес, тип ответа (Да/Нет или шкала), «N/A разрешён», «штрафной» критерий |

**В карточке диалога** у каждого критерия видно:
- ответ;
- полоску вероятностей вариантов, например «да 96% · нет 4%»;
- объяснение;
- ссылку «реплика N»: по клику транскрипт прокручивается к этому сообщению и подсвечивает его, а у звонков плеер
  перематывается на этот момент.

Если уверенность модели ниже 75%, критерий помечается **«Проверить»**.

**Типичный сценарий:**
1. **Подать апелляцию.** «Диалоги» → открыть диалог → блок **«Подать апелляцию»** в карточке: выбрать критерий, написать комментарий.
2. **Решить её.** Переключить роль на **«Проверяющий»** → «Апелляции» → «Подтвердить» или «Изменить» с причиной.
   В карточке появятся исходная оценка, решение и новый итог.
3. **Добавить новый критерий.** «Чек-листы» → добавить критерий, например «Оператор чихнул в чат» (тип Да/Нет, штрафной)
   → сохранить. В карточке диалога выбрать новую версию чек-листа → **«Оценить заново»**. Модель понимает критерий по
   его тексту, код менять не нужно.
4. **Дообучить модель.** Если модель ошибается на новом критерии, рассмотрите апелляции по нему минимум в 5 разных
   диалогах. Затем «Апелляции» → «Дообучение модели» → **«Дообучить модель по решениям»**. Это занимает секунды,
   перезапуск не нужен.

## 5. Консоль

```
npm run eval -- --group DEV                    оценить весь набор DEV (нужен запущенный сервис модели)
npm run eval -- --group DEV --limit 5          только первые 5 диалогов
npm run eval -- --ids p1-ru-001,p1-kz-003      конкретные диалоги
npm run accuracy -- --gt data/gt-holdout       сверить последние оценки с эталонной разметкой
npm test                                       автотесты (39 шт., сервис модели не нужен)
```

### Новый набор диалогов от организаторов

1. В файл `.env` впишите `CQA_API_URL=` — полную ссылку API организаторов без `&group_id=...` на конце.
2. Перезапустите приложение.
3. «Диалоги» → в поле `group_id` введите выданный код → **«Загрузить»** → **«Оценить все»**.

Набор сохранится в `data/<group_id>.json`. Можно и без API: положите файл с диалогами в `data/<имя>.json` (массив
диалогов, `{records:[...]}` или ответ API как есть) и загрузите его по имени.

## 6. Насколько модель точна

Сверка на 13 реальных диалогах, которые модель не видела при обучении (104 ответа):

| | Самый частый ответ | Правила (регулярки) | **cqa-local-v1** |
|---|---|---|---|
| Совпадение с эталоном | 76.0% | 74.0% | **82.7%** |
| macro-F1 по критериям | 42.3 | 52.4 | **71.1** |

**Сильные стороны:**
- находит все грубые ошибки, проверено на синтетике и на копиях реальных диалогов со вставленными нарушениями;
- одна оценка занимает около 0.1 с на процессоре и ничего не стоит.

**Слабые стороны:**
- хуже всего оценивает «корректность консультации» и «управление диалогом», потому что знаний о продуктах брокера
  у модели нет;
- критерий, которого модель не видела при обучении, она часто уверенно оценивает как «нет»; помогает дообучение по
  апелляциям.

Эталонная разметка — черновик, его ещё нужно проверить человеку. Подробный отчёт:
[local-model/REPORT.md](local-model/REPORT.md).

## 7. Обучение модели с нуля (необязательно)

Готовые веса уже лежат в `local-model/weights/cqa-local-v1.pt` (19.9 МБ), поэтому обучать ничего не нужно. Чтобы
повторить обучение:

```
npm run datagen                                              данные для обучения, около 1 минуты
local-model\.venv\Scripts\python.exe local-model\train.py    обучение, около 40–50 минут на процессоре
local-model\.venv\Scripts\python.exe local-model\predict.py
local-model\.venv\Scripts\python.exe local-model\evaluate.py --models majority,rules,cqa-local-v1 --detail gt-holdout
```

Для `npm run datagen` нужен Python, доступный как `py -3`. Как устроена модель — [local-model/README.md](local-model/README.md),
генератор данных — [local-model/datagen/README.md](local-model/datagen/README.md).

## 8. Если что-то не работает

| Симптом | Что сделать |
|---|---|
| «Модель не запущена (…)» при оценке | Не запущено окно «CQA model». Запустите `start.cmd` или `local-model\.venv\Scripts\python.exe local-model\serve.py` |
| `setup.cmd`: «Node.js 20+ is required» или «Python 3.10+ is required» | Установите программу из раздела 1 и перезапустите `setup.cmd` |
| Порт 3000 или 8000 занят | В `.env` задайте `PORT=3001` и/или `LOCAL_MODEL_PORT=8001` вместе с `LOCAL_MODEL_URL=http://127.0.0.1:8001` |
| Звонок не проигрывается | Ссылка на запись живёт около часа. Обновите карточку или нажмите «Открыть плеер» |
| Хочется начать с чистого листа | Остановите приложение и удалите папку `storage` (там оценки, апелляции, версии чек-листов) |

## 9. Устройство проекта

```
setup.cmd, start.cmd       установка и запуск в Windows
server/                    приложение: Node.js + Express
  index.js                 REST API
  model/                   клиент сервиса модели, сборка оценки, события диалога, сверка с эталоном
  scoring.js               формула итога (детерминированная)
  analytics.js, business.js  сводка, профили операторов, тревоги, экономия, коучинг
  store.js                 хранение в JSON-файлах (папка storage/)
  seed/checklist.default.json  стартовый чек-лист (8 критериев)
web/                       интерфейс: HTML + CSS + JS без сборщика
local-model/               модель: обучение (train.py), сервис (serve.py), веса, генератор данных, отчёт
data/                      наборы диалогов (DEV.json, SYNTH.json) и эталонная разметка (gt, gt-holdout, gt-fresh)
docs/                      задание и исходный чек-лист (PDF)
scripts/                   консольные команды: оценка, точность, генерация данных, демо, smoke-тесты
```

Формула итога: итог = Σ(вес × доля балла) / Σ весов × 100 по применимым критериям. N/A и «ручная проверка» в итог
не входят. Грубая ошибка на балл не влияет, это отдельный флаг.
