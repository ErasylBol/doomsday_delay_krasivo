# Обучающие данные для локальной модели CQA

Генератор синтетических диалогов с точной разметкой и аугментация реальных диалогов DEV. Цель — разнообразие:
темы, языки, каналы, поведение оператора и клиента, «новые» критерии вроде штрафа за чихание.

## Быстрый старт

Из папки `local-model/datagen`:
```
python generate.py --n 8000 --seed 7 --out ../data
python augment_dev.py --copies 6 --out ../data
python check.py --data ../data
```
Только стандартная библиотека Python 3.10+.

## Что получается в `local-model/data/`

| Файл | Что внутри |
|---|---|
| `synth_dialogs.json` | синтетические диалоги в формате API организаторов (`data.records[]`) |
| `synth_labels.jsonl` | разметка: ответы по стартовому чек-листу, доказательства, атомарные факты, сценарий, split |
| `aug_dev_dialogs.json`, `aug_dev_labels.jsonl` | реальные эталонные диалоги DEV со вставками (чих, эмодзи, капс, грубое нарушение и т.д.) |
| `question_bank.json` | все вопросы в формате критерия чек-листа: стартовые критерии + их перефразы, атомарные факты, «новые» критерии |
| `pairs_{train,val,test}.jsonl` | готовые пары «диалог × вопрос → ответ» для обучения |
| `pairs_zero_shot.jsonl` | пары по «новым» критериям, которых нет в обучении (проверка обобщения) |
| `SYNTH.json`, `gt-synth/` | выборка 150 диалогов для просмотра в UI и сверки модели с разметкой генератора |
| `stats.json` | распределения по языкам, темам, ответам, фактам; бейзлайн «частый ответ» |

## Разнообразие

- 18 тем брокера (тариф, вывод средств, пополнение, отклонённые заявки, вход, документы, налоговая справка, дивиденды,
  комиссии, перевод бумаг, маржинальная торговля, обмен валют, сбои приложения, баланс, отчёт, анкета...),
  у каждой — ответы разного качества (полный / без детали / частичный / размытый / ошибочный).
- RU / KZ / EN (50 / 25 / 25%), чаты и звонки (звонки с IVR, маскированием `[Имя скрыто]`, ISO-временем и шумом распознавания).
- Поведение оператора по каждому критерию чек-листа, включая редкие случаи: приветствие на чужом языке, переспросил
  известное, раскрыл данные до идентификации, ожидание без предупреждения, ответ невпопад и повтор вопроса клиентом,
  бессвязные реплики, молча закрыл чат, обрыв, клиент так и не сформулировал запрос, три вида грубых нарушений.
- 16 «новых» поведений оператора (чих, кашель, эмодзи, сленг, «ты», капс, опечатки, просьба об оценке, ссылка,
  конкуренты, личные темы, обещание перезвонить, извинение, смешение языков, обвинение клиента, еда)
  и отвлекающие поведения КЛИЕНТА (чих, эмодзи, капс) — чтобы модель учила «оценивается только оператор».

## Формат разметки (`synth_labels.jsonl`)

```json
{"conversation_id": "syn-ru-c-00000",
 "answers":  {"c01": "yes", "c02": "yes", "c03": "no", "c04": 20, "c05": "yes", "c06": 10, "c07": "no", "c08": "no"},
 "evidence": {"c03": [12, 13, 15], "c07": [19], ...},
 "ambiguous": ["c05"],
 "facts": {"op_sneezed": {"v": false, "ev": []}, "identity_verified": {"v": true, "ev": [13, 15]}, ...},
 "scenario": {...}, "split": "train", "labeled_by": "generator"}
```
`answers` — в том же формате, что `data/gt/*.json`. `ambiguous` — критерии, где разметчики могли бы разойтись
(например, «ты» и вежливость); их стоит исключать из метрик или учить с меньшим весом.

## Формат пар (`pairs_*.jsonl`)

```json
{"d": "syn-ru-c-00000", "q": "n_op_sneezed", "w": 1, "y": "no", "ev": []}
```
- `d` — id диалога (`synth_dialogs.json`), `q` — id вопроса в `question_bank.json`, `w` — номер формулировки в `wordings`,
  `y` — ответ (`yes` / `no` / `na` / ступень шкалы), `ev` — индексы реплик-доказательств (для обучения внимания).
- Вопрос в `wordings[w]` — это объект критерия (`name`, `description`, `type`, `levels`, `polarity`, `na_allowed`,
  `na_condition`), то есть ровно то, что модель получит из редактора чек-листа в работе. Варианты ответа строятся из него:
  yesno → да / нет (+ N/A, если разрешён); scale → ступени `levels`.
- На диалог: 8 критериев стартового чек-листа (40% — в перефразированной формулировке) + до 3 положительных и 3
  отрицательных атомарных / новых вопросов.

## Сплиты и утечка

- `split` назначен диалогу целиком: train 80% / val 10% / test 10%. Пары не пересекаются по диалогам.
- `zero_shot` вопросы (кашель, еда на рабочем месте, конкуренты) в train-пары НЕ попадают — по ним меряется,
  справляется ли модель с критерием, которого не видела (как «чихание» от организаторов).
- Аугментация DEV: копии диалогов из `data/gt-holdout` имеют `split=test`. Не обучайтесь на них.

## Проверка на синтетике через приложение

Выборка `data/SYNTH.json` — обычный набор для UI. Оценка моделью и сравнение с разметкой генератора:
```
npm run eval -- --group SYNTH
npm run accuracy -- --gt local-model/data/gt-synth --verbose 1
```

## Как расширять

- Новая тема — словарь в `topics.py` (3 языка, ответы разного качества).
- Новое поведение оператора — фразы в `banks.py` (`novel`), вопрос в `questions.py` (`N`), при необходимости эффект
  на стартовые критерии в `labels.py`.
- Изменился стартовый чек-лист — правится только `labels.py`.

## Ограничения

- Казахские тексты — черновик, нужна вычитка носителем.
- Синтетика шаблонна по структуре (бот → эскалация → оператор, как в DEV).
- «Корректность консультации» размечена по уровню ответа из сценария, а не по смыслу: модель научится отличать
  полный / частичный / размытый / ошибочный ответ только в пределах этих 18 тем.
