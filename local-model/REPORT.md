# Отчёт: локальная модель cqa-local-v1

Своя модель оценки операторов, обученная с нуля (случайная инициализация, без предобученных весов, эмбеддингов и
токенизаторов, без внешних API во время оценки). Все цифры ниже — из реальных прогонов 08.11.2026, команды в конце.
Ничего не округлено в пользу модели; где сравнение неполное — сказано прямо.

## Коротко

| | Частый ответ | Только правила | **cqa-local-v1** |
|---|---|---|---|
| Реальный эталон `gt-holdout`: точность | 76.0% | 74.0% | **82.7%** |
| `gt-holdout`: macro-F1 (среднее по 8 критериям) | 42.3 | 52.4 | **71.1** |
| `gt-holdout`: balanced accuracy | 47.9 | 59.2 | **73.5** |
| Полнота грубых ошибок (аугм. holdout / синтетика) | 50.0% / 0% | 66.7% / 35.1% | **100% / 100%** |
| Новые критерии, которых модель не видела (zero-shot), macro-F1 | 48.8 | 92.1 | **56.8** |
| Время: один диалог / весь DEV (65) | — | — | **≈ 0.1 с** (≤ 0.18 с на 115 реплик) / **15.9 с** на CPU |
| Стоимость | $0 | $0 | **$0** |

Модель обходит оба бейзлайна на реальном отложенном эталоне по всем главным метрикам, ловит все грубые ошибки, работает
за десятые доли секунды на CPU и ничего не стоит. Слабые места — «управление диалогом» и «корректность консультации»,
а также критерии, которых модель не видела на обучении. Для них есть дообучение по апелляциям — оно помогает, но немного (раздел 6).

## 1. Протокол

- **Модель:** ансамбль из 3 моделей (seed 1, 2, 3) по 3.30 млн параметров, всего **9 892 461** параметров, веса
  **19.9 МБ** (fp16), `local-model/weights/cqa-local-v1.pt`. Устройство — `README.md`.
- **Обучение:** 6351 синтетический диалог (`pairs_train`, 88 153 пары) + реальный `data/gt` (20 диалогов, вес выборки ×6)
  + аугментация DEV train (120 копий диалогов из `data/gt`) + самообучающие «пробные» вопросы. Ранняя остановка и калибровка
  температуры — по `pairs_val` + `gt-fresh` + аугментации val + zero-shot val (невиданные вопросы на синтетических val-диалогах).
- **Утечка исключена:** `gt-holdout` (13 диалогов) и 78 его аугментированных копий не участвуют ни в обучении, ни в выборе
  эпохи, ни в калибровке (`data.assert_no_leak` проверяет при каждом запуске). Синтетика разбита по диалогам. Невиданные
  вопросы (кашель, еда, конкуренты, обещание перезвонить) в обучение не попадают.
- **Наборы для отчёта:**
  - `gt-holdout` — реальный эталон, 104 ответа. Это черновик разметки ИИ-ассистента: на 13 диалогах разброс большой, один ответ = 1 п.п.
  - `aug-test` — копии holdout со вставками (чих, грубость и т.д.), 1566 ответов.
  - `synth-test` — 805 синтетических диалогов, 11 172 ответа.
  - `zero-shot` — 4 невиданных вопроса на 883 диалогах, 3532 ответа.
- **Метрики** (`evaluate.py`): точность; macro-F1 и balanced accuracy по каждому критерию, усреднённые по критериям;
  полнота «нет»; N/A precision/recall; полнота грубых; надёжность уверенности; Brier.

## 4. Новые критерии без обучения (zero-shot)

| Вопрос (не было в обучении) | Положительных | Правила: полнота / точность | cqa-local-v1: полнота / точность | «Проверить» у модели |
|---|---|---|---|---|
| Кашель в чате | 28 | 1.00 / 1.00 | 0.46 / 1.00 | 8 |
| Еда на рабочем месте | 33 | 1.00 / 0.70 | 0.00 / — | 0 |
| Упоминание конкурентов | 50 | 1.00 / 0.54 | 0.00 / 0.00 | 17 |
| Обещание перезвонить | 51 | 1.00 / 0.80 | 0.00 / — | 1 |

Честно:
- Без обучения модель распознаёт только критерии, где текст вопроса лексически близок к реплике («кашляет» ↔ «*кашляет*»,
  «кхе-кхе»). Конкурентов (Halyk, Jusan) по описанию «другая компания» без знаний о мире не найти.
- Хуже того, на таких критериях она уверенно отвечает «нет», и подсветка «Проверить» почти не срабатывает.
- Правила здесь — верхняя оценка: регулярки писались, зная фразы генератора.
- «Штраф за чихание» (он в обучении был, но формулировку судьи модель не видела) работает хорошо — раздел 6.

Что сделано для обобщения:
- канал лексического сопоставления токенов вопроса с токенами реплик (с поправкой на фон диалога);
- самообучающие «пробные» вопросы («оператор написал «X»»);
- прямой путь «совпало в реплике оператора → «да»».

Это подняло zero-shot val с 0.49 до 0.57–0.60 macro-F1. Мало, но это всё, что удалось за отведённое время.

Высокая уверенность действительно означает более точный ответ. Исключение — невиданные критерии (раздел 4).

## 6. Сценарий защиты: новый критерий в редакторе (`node scripts/local-demo.mjs`)

Через тот же REST, что и UI. Метрики считаются на 300 синтетических test-диалогах (группа SYNTHTEST), которых не было в обучении.

1. **«Штраф за чихание»** (`polarity: negative`, описание как в банке вопросов) добавлен в чек-лист:
   - 300 диалогов: найдено 10 из 11 чиханий оператора, 0 ложных срабатываний;
   - доказательство указывает на реплику «Апчхи! Кешіріңіз.»;
   - в реальном DEV (65) — 0 срабатываний: чиханий там нет.
2. **«Оператор обещал перезвонить»** (модель не видела):
   - до дообучения найдено 0 из 15 обещаний, «Проверить» — у 1 диалога из 300: модель уверенно говорит «нет»;
   - 10 апелляций с решением проверяющего (5 «да», 5 «нет», диалоги не из test), затем «Дообучить» — 7.1 с на CPU;
   - после дообучения найдено 6 из 15 (полнота 40%), ложных «да» 34 (точность «да» 15%);
   - «Проверить» теперь у 136 диалогов: модель честно показывает, что не уверена, и проверяющий видит кандидатов.

Дообучение обучает адаптер решающего слоя: 4 «ключевых слова» в пространстве сопоставления, детектор по репликам
оператора, сдвиг вектора вопроса. Офлайн-сравнение вариантов дообучения показало главное: апелляции смещены к ошибкам
модели (5 «да» из 10 при реальной доле 5%), и наивное дообучение даёт сотни ложных «да» (точность 7–14%). Поэтому
исправления проверяющих взвешиваются так, чтобы их эффективная доля была ≤ 1:3. На 10 примерах (5+5) из val:
полнота 0.60 / точность 0.60; на 20 (10+10): 0.60 / 0.32. Положительных примеров мало, а одна и та же мысль
сказана шестью способами на трёх языках — 5 примеров их не покрывают. Нужны десятки решений.

## 8. Как шли итерации (чтобы цифрам можно было верить)

| Версия | Что изменилось | val synth / real / zero-shot (macro-F1) | gt-holdout |
|---|---|---|---|
| quick (1 эпоха) | базовая архитектура | 0.64 / 0.63 / — | 75.0% / 54.1 |
| dev1 (6 эпох, 1 seed) | + выбор по val | 0.94 / 0.81 / 0.49 | не смотрели |
| dev2 | + пробные вопросы | 0.96 / 0.83 / 0.49 | не смотрели |
| dev3 | + сопоставление относительно фона | 0.94 / 0.81 / 0.55 | не смотрели |
| dev4 | + прямой путь «совпало → да» | 0.94 / 0.82 / 0.60 | не смотрели |
| финал-1 (3 seed, 5 эпох, 39.5 мин) | итоговая конфигурация | 0.95 / 0.80 / 0.57 | 75.0% / 61.6 |
| **финал-2 (49.0 мин)** | исправлен паддинг в текстовом энкодере (ответ зависел от состава батча) | 0.96 / 0.82 / 0.57 | **82.7% / 71.1** |

Решения принимались только по val. Holdout смотрели дважды:
- после первой эпохи — проверка конвейера;
- после финала-1.

Финал-2 появился из-за ошибки (результат зависел от батча), а не ради holdout. Его выбрали, потому что он лучше на val.
Разница финал-1 → финал-2 на holdout (+7.7 п.п.) больше, чем на val (+1.5 п.п.): на 104 ответах это в пределах шума.
Честная оценка качества на реальных данных — примерно 75–83% точности и macro-F1 62–71.

## 9. Ограничения

- Мало реального: 20 размеченных диалогов для обучения, holdout — 13 диалогов. Эталон — черновик ИИ-ассистента.
- Синтетика шаблонна: язык реальных операторов модель знает плохо, KZ-тексты не вычитаны носителем.
- Шкалы «консультация» и «управление диалогом» модель с нуля оценивает плохо: знаний о продуктах брокера у неё нет.
- Невиданные критерии: часто уверенное «нет» без подсветки «Проверить». Дообучение помогает частично; нужны десятки решений.
- Флаги грубых ошибок на DEV: модель ставит 6, разметки грубых ошибок по всему DEV нет — сверить не с чем.

## Как воспроизвести

```
npm run datagen
local-model\.venv\Scripts\python.exe local-model\baselines.py
local-model\.venv\Scripts\python.exe local-model\train.py
local-model\.venv\Scripts\python.exe local-model\predict.py
local-model\.venv\Scripts\python.exe local-model\evaluate.py --models majority,rules,cqa-local-v1 --detail gt-holdout
local-model\.venv\Scripts\python.exe local-model\serve.py           (второе окно: npm start)
npm run eval -- --group DEV  &&  npm run accuracy -- --gt data/gt-holdout
node scripts/local-demo.mjs
```
