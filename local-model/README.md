# Модель CQA (cqa-local-v1)

Своя модель оценки операторов: архитектура и веса обучены с нуля (случайная инициализация), без предобученных весов,
эмбеддингов и токенизаторов, без внешних API во время оценки. Диалог читается один раз, на все вопросы чек-листа модель
отвечает **вероятностями** по вариантам. Вопрос — это **текст** критерия из редактора, поэтому новый критерий работает
без правки кода. Цифры и сравнение с бейзлайнами — [REPORT.md](REPORT.md). Как запустить всё приложение —
[README в корне](../README.md).

## Сервис модели (Windows, веса уже в репозитории)

```
py -3 -m venv local-model\.venv
local-model\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
local-model\.venv\Scripts\python.exe -m pip install -r local-model\requirements.txt
local-model\.venv\Scripts\python.exe local-model\serve.py
```
Сервис слушает только `127.0.0.1:8000` (порт — `LOCAL_MODEL_PORT`). Проверка: открыть http://127.0.0.1:8000/health.
Приложение (`npm start`) обращается к нему по `LOCAL_MODEL_URL` (по умолчанию http://127.0.0.1:8000).

## Что видно в интерфейсе

- В карточке диалога у каждого критерия — полоска вероятностей («нет 82% · да 15% · …»), уверенность и объяснение,
  собранное по шаблону: ответ, вероятность, цитата реплики-доказательства; для «Нет» — проверенный участок, для N/A — условие.
- Уверенность < 0.75 → подсветка «Проверить».
- Экран «Апелляции»: блок «Дообучение модели». Кнопка
  «Дообучить модель по решениям» берёт рассмотренные апелляции по критерию (≥ 5 разных диалогов), дообучает решающий слой
  под этот критерий (секунды на CPU) и сразу применяет его к новым оценкам. Перезапуск не нужен.

## Обучение с нуля (воспроизводимо, seed 1, 2, 3)

```
npm run datagen                                   данные: синтетика + аугментация DEV + события (≈ 1 мин)
local-model\.venv\Scripts\python.exe local-model\baselines.py     бейзлайны «частый ответ» и «правила»
local-model\.venv\Scripts\python.exe local-model\train.py        ансамбль из 3 моделей → local-model\weights\cqa-local-v1.pt
local-model\.venv\Scripts\python.exe local-model\predict.py      предсказания на тестовых наборах
local-model\.venv\Scripts\python.exe local-model\evaluate.py --models majority,rules,cqa-local-v1 --detail gt-holdout
```
`train.py` по умолчанию работает на CPU (`--device auto` — CUDA, если есть). Время и параметры пишутся в веса
(`GET /health`, поле `trained_at`) и в лог.

## Как устроено

```
диалог → реплики → [текстовый энкодер] + признаки реплик → [энкодер диалога, 2 слоя трансформера] → U
вопрос (name + description + «Да = нарушение»), варианты (да / нет / «N/A: условие» / ступени шкалы)
       → [тот же текстовый энкодер] → q, o_1..o_M
лексическое сопоставление токенов вопроса с токенами реплик (бот исключён) → S
q → 2 шага cross-attention по U (смещение S) → контекст → оценка каждого варианта → softmax
```
- **Токенизация без словаря**: хеши символьных n-грамм 3–5, слова и формы токена (CAPS, цифры, символы) в 2^18 корзин;
  hash embeddings (две строки из таблицы 2^14×64 + веса важности корзины). Одинаково для RU/KZ/EN, терпимо к ASR.
- **Признаки реплики**: роль, события `detectEvents` (эскалация, идентификация, обрыв, удержание, закрытие, первая/последняя
  реплика оператора, долгий ответ), паузы из `offsets()`, позиция, язык, канал, форма текста. События считает Node
  (`server/model/events.js`): для обучения — `npm run events` → `data/events.json`, в рантайме Node присылает их в запросе.
- **Доказательства**: веса внимания по репликам → `evidence` (топ реплик оператора/системы), `checked_range` (связный участок
  с 80% массы внимания). Вспомогательная потеря учит внимание указывать на реплики-доказательства из разметки.
- **Обучение**: синтетика `pairs_train` + реальный `data/gt` (вес выборки ×6) + аугментация DEV train (×3); кросс-энтропия
  с весами классов и сглаживанием; перевес диалогов с редкими ответами; самообучающие «пробные» вопросы
  (`cqa_local/probes.py`: «оператор написал «X»» — учат сопоставлять текст критерия с репликами оператора). Ранняя остановка по
  `pairs_val` + `gt-fresh` + аугментации val + zero-shot val. Калибровка — температура на тип вопроса.
- **Утечка**: `gt-holdout` и его аугментированные копии (`split=test`) не участвуют ни в обучении, ни в выборе эпохи, ни в
  калибровке (`assert_no_leak`). Невиданные вопросы (кашель, еда, конкуренты, «обещание перезвонить») в обучение не попадают.
- **Нет c01..c08 в коде модели и интеграции**: вопрос — текст критерия. Id встречаются только в чтении эталона для метрик
  (`cqa_local/data.py`) и в генераторе данных (`datagen/labels.py`).

## API сервиса

`GET /health` → `{ model, params, members, adapters, temps, trained_at }`

`POST /v1/decide`
```
{ "record": { conversation_id, channel, language, transcript: [...] },
  "events": [ ...detectEvents ], "offsets": [ ...offsets ]   (необязательно; без него — разбор timestamp в Python),
  "questions": { "<ключ>": { "type": "noul"|"choice"|"score", "criterion": { name, description, type, levels, polarity,
                 na_allowed, na_condition }, "options": [ { "key": "yes", "text": "Да" }, ... ] } } }
→ { "model": "cqa-local-v1", "duration_ms": 12, "operator_name": "Алина"|null,
    "answers": { "<ключ>": { "choice": "yes", "probabilities": { "yes": 0.82, "no": 0.18 }, "confidence": 0.82,
                             "score": 13.4 (шкала: Σ p·value), "evidence": [9], "checked_range": [9, 14] } } }
```
Тексты вопроса и вариантов модель строит из `criterion` сама (`cqa_local/questions.py`), ключи вариантов совпадают с
`server/model/questions.js`.

`POST /v1/finetune` `{ question: { criterion }, examples: [ { record, events, offsets?, answer } ] }` — минимум 5 примеров с
допустимым ответом, иначе 400. Энкодеры и базовый решающий слой заморожены. На каждую модель ансамбля обучается адаптер
решающего слоя (`cqa_local/finetune.py`):
- 4 «ключевых слова» в пространстве лексического сопоставления;
- детектор их совпадения в репликах оператора;
- сдвиг вектора вопроса.

Исправления проверяющих взвешиваются до доли ≤ 1:3: апелляции смещены к ошибкам модели. Занимает секунды на CPU,
бюджет — 50 с. Адаптер сохраняется в `weights/adapters/<хеш нормализованного текста вопроса>.pt` и применяется `decide`
к вопросу с тем же текстом. Адаптер старого формата пропускается с предупреждением.

## Файлы

```
local-model/
  cqa_local/        пакет: text (хеш-токенизация), features (признаки реплик), model, batch, infer (ансамбль, доказательства),
                    finetune (адаптеры), probes (пробные вопросы), data (наборы и защита от утечки), metrics, questions
  train.py          обучение ансамбля + калибровка → weights/cqa-local-v1.pt
  predict.py        предсказания на тестовых наборах → runs/preds/<модель>/
  evaluate.py       метрики: точность, macro-F1, bal. accuracy по критериям, «нет», N/A, грубые, языки, каналы, надёжность, Brier
  baselines.py      «частый ответ» и «только правила»
  serve.py          FastAPI-сервис
  export_events.mjs выгрузка событий из server/model/events.js
  weights/          веса (в репозитории; adapters/ — дообучение, создаётся кнопкой)
  datagen/, data/   генератор данных и данные (см. datagen/README.md)
```

## Ограничения (честно)

- Модель маленькая и выучила язык в основном на шаблонной синтетике: на реальных диалогах она ошибается заметно чаще, чем на синтетике
  (см. REPORT.md), особенно в «корректности консультации» и «управлении диалогом» — знаний о продуктах брокера у неё нет.
- Критерий, которого модель не видела, она часто уверенно оценивает как «нет»: подсветка «Проверить» срабатывает не всегда.
  Рабочий путь — 5–10 решений по апелляциям и «Дообучить» (см. сценарий в REPORT.md).
- Эталон `data/gt*` — черновик разметки ИИ-ассистента; `gt-holdout` — 13 диалогов (104 ответа), разброс метрик большой.
- Казахские тексты синтетики — черновик, без вычитки носителем.
